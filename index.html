What is a problem — and what makes it an optimization problem?

In computing, a problem is a clearly described situation where you have some input and need to find the best or correct output. An optimization problem is a specific kind: there may be many possible answers, but you want the one that is the best by some measure — the highest value, the lowest cost, the shortest path, and so on.

Not every problem has one clear right answer. In optimization, the challenge is not just finding a solution, but finding the best possible one — often from a huge number of possibilities.

What is the 0/1 Knapsack problem?

Imagine you are going on a trip and you have a backpack that can only carry a limited total weight — say, 10 kilograms. You have several items in front of you, and each item has two properties:

⚕ Weight
How heavy the item is. This is the cost of packing it. Every item you include uses up some of your bag’s limited space.
✨ Value
How useful or important the item is. This is what you gain by packing it. Your goal is to pack items that together give you the most total value.

The bag has a capacity — a hard limit on how much total weight it can hold. You want to choose a combination of items so that the total weight stays within the capacity, and the total value is as high as possible.

This is the Knapsack problem — and it is one of the most famous optimization problems in computer science.

What does "0/1" mean?

The name 0/1 Knapsack comes from a simple rule: each item can only be either fully taken or completely left behind.

1 — Take the whole item
You pack the entire item: you get its full value and it takes its full weight.
0 — Leave the item behind
You do not pack the item at all: no value gained, no weight used.

You cannot take half of an item or a quarter of it. Either it goes in the bag completely, or it does not go in at all. This is what makes the problem hard — and interesting.

For example, if you have a laptop (heavy, very valuable) and a book (light, somewhat valuable), you cannot take half a laptop. You either pack the whole laptop or you leave it behind entirely.

Why does this problem matter?

The 0/1 Knapsack problem appears in many real-world situations wherever you have limited resources and binary choices:

  • ▸ Project budgeting: Which projects should a company fund this year given a limited budget?
  • ▸ Cargo loading: Which boxes should go on a truck with a fixed weight limit?
  • ▸ Feature selection: Which features should a software team ship given limited development time?
  • ▸ Investment decisions: Which assets should be included in a portfolio with a fixed total cost?

In all of these cases, you must choose a subset of options that fits within a constraint and maximizes some objective. The difficulty is that with n items there are 2n possible subsets — even with just 30 items, that is over one billion combinations to consider. Finding the best one efficiently is a genuine challenge.

Three Approaches to 0/1 Knapsack
Each method has different trade-offs in terms of correctness, speed, and complexity. Understanding all three helps you see why Dynamic Programming is the right tool for this problem.
🔍

Brute Force

Try every possible subset
O(2ⁿ)

Core idea: Enumerate all 2n possible subsets of items. For each subset, check whether the total weight fits within capacity W. Among all valid subsets, return the one with the highest total value.

With 3 items, there are 8 subsets: {}, {i1}, {i2}, {i3}, {i1,i2}, {i1,i3}, {i2,i3}, {i1,i2,i3}. At n=20, this becomes 1,048,576 subsets. At n=30, over 1 billion. The approach is correct but completely impractical for any real input.

When it is useful: Only for very small inputs (n ≤ 15) or as a correctness baseline when verifying other algorithms.

Space
O(n)

Dynamic Programming

Build a table, reuse results
O(n·W)

Core idea: Build a 2D table K[i][w] where each cell stores the best value achievable using the first i items with capacity w. Fill the table bottom-up by applying the recurrence: K[i][w] = max(K[i−1][w], vi + K[i−1][w−wi]).

This works because the problem has overlapping subproblems (the same sub-answers are needed many times) and optimal substructure (the global optimum is built from locally optimal sub-answers). DP stores each result once and reuses it, replacing exponential re-computation with a compact table.

When it is useful: The standard approach for 0/1 Knapsack when W is reasonably bounded. This is what the Visualizer demonstrates step by step.

Greedy

Pick best ratio first — but can fail
O(n log n)

Core idea: Sort items by their value-to-weight ratio (v/w) in descending order. Pick items greedily from the top of this list, adding each one if it fits within the remaining capacity. Stop when no more items fit.

This sounds efficient — take the most "valuable per kg" item first. And it is fast: O(n log n) for the sort. But for 0/1 Knapsack, it does not guarantee the optimal answer. Picking a high-ratio item can leave awkward remaining capacity that two or more smaller items would have filled better in combination.

When it is useful: Greedy is only optimal for Fractional Knapsack, where you can take partial items. For 0/1 Knapsack, use Dynamic Programming.

O(n)

Why DP works: Two key properties
Optimal Substructure & Overlapping Subproblems ►

Optimal Substructure: The optimal solution to K[i][w] depends only on optimal solutions to K[i−1][w] and K[i−1][w−wi]. We can safely build the global optimum from smaller optimal sub-answers.

Overlapping Subproblems: Without DP, a recursive approach would recompute the same K[i][w] values many times across different branches. DP stores each answer in the table and looks it up in O(1), turning exponential recursion into O(nW) iteration.

💡 Key insight: Brute force explores all 2n subsets. DP compresses this into a (n+1)×(W+1) table by recognizing that many branches ask the same sub-questions — and answering each question only once.
⚠ Common mistake: Confusing DP with Divide & Conquer. D&C subproblems are independent (like merge sort). DP subproblems overlap — this is the critical difference.
The Include / Exclude Recurrence ►

Every cell K[i][w] answers: "What is the best value using the first i items with capacity w?"

EXCLUDE item i: Best value = K[i−1][w] — the best result without this item at the same capacity.
INCLUDE item i (only if wi ≤ w): Gain vi in value, reduce remaining capacity. Best result = vi + K[i−1][w−wi].
Recurrence: K[i][w] = max(K[i−1][w], vi + K[i−1][w−wi]) — always take the better option.

Base cases: K[0][w] = 0 for all w, and K[i][0] = 0 for all i. The final answer is K[n][W].

Key Differences — What Every Student Should Know
Brute force is correct but exponential. It checks every possible combination, so it is guaranteed to find the optimal answer. The cost is O(2n) which becomes unusable past n ≈ 20.
Dynamic Programming is both correct and efficient. It stores sub-answers in a table and reuses them, reducing complexity from O(2n) to O(nW). This is the right choice for 0/1 Knapsack.
Greedy is fast but cannot guarantee optimality for 0/1 Knapsack. Picking the highest ratio item first can block combinations of other items that would produce a higher total value. Without fractional selection, the greedy assumption breaks.
Why DP beats brute force: Both are correct. DP wins on efficiency by exploiting overlapping subproblems — the same sub-question is answered once and stored, instead of being re-explored exponentially. A (n+1)×(W+1) table replaces the entire 2n decision tree.
Formal Recurrence & Correctness Proof

The DP recurrence K[i][w] = max(K[i−1][w], valuei + K[i−1][w−weighti]) is not just a formula — it can be formally proven correct using induction, and its O(nW) complexity follows directly from how the table is filled. Click below to see the full explanation.

② Brute Force Decision Tree Brute Force

Brute force explores all 2n possible subsets by making a binary decision (include or exclude) for each item. With n=4 items below, this creates 24 = 16 leaf nodes in the decision tree.
How to read this tree:
  • Each level represents a decision about one item: include it (right branch) or exclude it (left branch).
  • As you go deeper, the current weight and value accumulate with each include decision.
  • Leaf nodes are complete subsets. Those within weight capacity are valid; those exceeding it are rejected.
  • Among all valid leaves, brute force picks the one with the highest value — this is the optimal solution.
  • With n=4 items, there are 24=16 subsets to check. DP compresses this entire tree into a compact (n+1)×(W+1) table.

✉ Sorting & Searching Algorithms — Key Section

✕

Before we look at how each algorithm solves the 0/1 Knapsack problem, it is important to understand the role that sorting and searching play in the approaches we compare. These are not background details — they directly determine the time complexity and behaviour of each method.

Sorting — Used in the Greedy Approach

The greedy algorithm relies entirely on sorting items by their value-to-weight ratio in descending order before making any selection. This is not a trivial step — it determines the entire sequence of decisions the algorithm makes.

The sorting step uses a comparison-based algorithm such as Merge Sort or QuickSort, both of which run in O(n log n) time. This is exactly where the greedy algorithm's overall time complexity of O(n log n) comes from — the selection step itself is just O(n), but it is dominated by the sort.

Example — Sorting by v/w ratio
Three items with ratios: 3.0, 5.0, 4.0
After sorting (descending): 5.0, 4.0, 3.0
Greedy picks items in exactly that order until capacity is exceeded.

So the behaviour of the greedy method depends directly on the sorting result being correct. A different item order would produce a different (and potentially worse) selection. Sorting is not just a pre-processing step — it is the algorithm's decision-making foundation.

Searching — Used in the DP Approach

Dynamic Programming does not sort items. Instead, it uses a form of structured table lookup — a searching process — to retrieve previously computed sub-answers in O(1) time.

When filling cell K[i][w], the algorithm must look up two previously computed values:

DP Lookup pattern
Exclude: look up K[i−1][w]   (row above, same column)
Include: look up K[i−1][w − wi]   (row above, earlier column)

Each of these is a direct table lookup — an O(1) operation. The DP table acts as a search cache: rather than re-exploring every combination, the algorithm searches the table for the answer to each sub-problem, finding it instantly. This is the mechanism that replaces O(2n) brute-force exploration with O(nW) efficient filling.

Additionally, during traceback, the algorithm performs a sequential O(n) search through the table rows — walking backwards from K[n][W] to identify which items were selected.

Summary

At a glance
Greedy: Sort by v/w ratio → O(n log n) dominated by sort
DP Fill: Table lookup per cell → O(1) per lookup, O(nW) total
DP Traceback: Sequential row search → O(n)

∞ Recurrence & O(nW) Proof

✕

A — The DP Recurrence

The core of the dynamic programming solution is a recurrence relation — a formula that expresses the answer to a larger problem in terms of smaller problems we have already solved.

K[i][w] means:

The best total value we can achieve using the first i items with a knapsack capacity of exactly w.

When the current item fits (weighti ≤ w):
K[i][w] = max( K[i−1][w],   valuei + K[i−1][w − weighti] )
When the current item is too heavy (weighti > w):
K[i][w] = K[i−1][w]

What each part means in plain language:

Exclude
K[i−1][w] — We skip item i entirely. The best we can do is whatever was achievable using the first i−1 items with the same capacity w. Nothing about item i changes the result.
Include
valuei + K[i−1][w − weighti] — We pack item i. We gain its value immediately, and the remaining capacity shrinks by its weight. The best result for that remaining capacity, using only the earlier items, is given by K[i−1][w − weighti].
max()
We always choose whichever option gives the higher total value. If including gives more, we include. If excluding is better, we exclude. We never guess — we compute both options and pick the best.
💡 Base cases: K[0][w] = 0 for all w (no items, no value). K[i][0] = 0 for all i (zero capacity, cannot pack anything). Every other cell is built on top of these foundations.

B — Time Complexity: O(nW)

The DP solution fills a table with (n + 1) rows and (W + 1) columns, where n is the number of items and W is the knapsack capacity.

Why O(nW):
• There are (n + 1) rows — one for zero items, then one for each of the n items.
• There are (W + 1) columns — one for each possible capacity from 0 to W.
• Every single cell is filled exactly once — we never revisit a cell.
• Filling each cell takes constant work: look up two values, take the max, write one result.
• Total cells = (n + 1) × (W + 1) ≈ nW
• Therefore, total running time = O(nW).

This is dramatically better than brute force O(2n). With n=20 and W=20, brute force checks over 1 million subsets. DP fills 20×20 = 400 cells. The table replaces the entire exponential search tree.

C — Why DP Is Correct: A Simple Proof by Induction

We will show that for every cell K[i][w], the value stored is exactly the maximum value achievable using the first i items with capacity w. This uses a technique called mathematical induction — we prove it is true for the smallest cases, then show it stays true as we build up.

Base idea

We want to show: K[i][w] = the correct optimal value for items 1 through i with capacity w. If we can show this is true starting from the simplest cases, and that it stays true every time we add a new item, then by the time we reach K[n][W] we know it holds the correct final answer.

Base case
Row 0 (no items): K[0][w] = 0 for every capacity w. This is correct — with zero items available, the best value you can achieve is always 0, regardless of how much space the bag has.

Column 0 (zero capacity): K[i][0] = 0 for every item count i. This is also correct — if the bag has zero capacity, you cannot pack anything, so the best value is always 0.
Hypothesis
Assume it works for all smaller subproblems. Specifically, assume that for all cells in rows 0 through i−1, K[i−1][w] already holds the correct optimal value for those items and that capacity. In other words: assume every cell above the current row is already correct.
Induction step
Now show K[i][w] is also correct. We consider item i and capacity w. There are exactly two possibilities in any valid selection of items:

Case 1 — item i is NOT included: The optimal selection uses only items from 1 to i−1. By our assumption, K[i−1][w] already holds this value correctly.

Case 2 — item i IS included (only possible if weighti ≤ w): We gain valuei from item i, and the remaining capacity is w − weighti. The best we can do with that remaining capacity using items 1 to i−1 is K[i−1][w − weighti], which is also already correct by assumption.

We take the maximum of both cases: max(K[i−1][w], valuei + K[i−1][w − weighti]). Since both options are computed correctly, the maximum is also correct.
Conclusion
By induction, every cell K[i][w] is filled correctly. In particular, K[n][W] — the bottom-right corner of the table — holds the correct optimal value using all n items with the full capacity W. This is the answer we want.

Complexity: We fill (n+1)(W+1) cells exactly once. Each fill is O(1). Total time = O(nW). Since this is much smaller than O(2n) for any reasonably bounded W, DP is the practical choice for solving 0/1 Knapsack.
✓ Summary: The recurrence is correct because every decision (include or exclude) uses previously computed optimal answers. The complexity is O(nW) because we fill each of the (n+1)(W+1) cells exactly once with constant-time work. The table is both a storage device and a proof that we never recompute anything.

C — Why DP Is Correct: A Simple Proof by Induction

We will show that for every cell K[i][w], the value stored is exactly the maximum value achievable using the first i items with capacity w. This uses a technique called mathematical induction — we prove it is true for the smallest cases, then show it stays true as we build up.

Base idea

We want to show: K[i][w] = the correct optimal value for items 1 through i with capacity w. If we can show this is true starting from the simplest cases, and that it stays true every time we add a new item, then by the time we reach K[n][W] we know it holds the correct final answer.

Base case
Row 0 (no items): K[0][w] = 0 for every capacity w. This is correct — with zero items available, the best value you can achieve is always 0, regardless of how much space the bag has.

Column 0 (zero capacity): K[i][0] = 0 for every item count i. This is also correct — if the bag has zero capacity, you cannot pack anything, so the best value is always 0.
Hypothesis
Assume it works for all smaller subproblems. Specifically, assume that for all cells in rows 0 through i−1, K[i−1][w] already holds the correct optimal value for those items and that capacity. In other words: assume every cell above the current row is already correct.
Induction step
Now show K[i][w] is also correct. We consider item i and capacity w. There are exactly two possibilities in any valid selection of items:

Case 1 — item i is NOT included: The optimal selection uses only items from 1 to i−1. By our assumption, K[i−1][w] already holds this value correctly.

Case 2 — item i IS included (only possible if weighti ≤ w): We gain valuei from item i, and the remaining capacity is w − weighti. The best we can do with that remaining capacity using items 1 to i−1 is K[i−1][w − weighti], which is also already correct by assumption.

We take the maximum of both cases: max(K[i−1][w], valuei + K[i−1][w − weighti]). Since both options are computed correctly, the maximum is also correct.
Conclusion
By induction, every cell K[i][w] is filled correctly. In particular, K[n][W] — the bottom-right corner of the table — holds the correct optimal value using all n items with the full capacity W. This is the answer we want.

Complexity: We fill (n+1)(W+1) cells exactly once. Each fill is O(1). Total time = O(nW). Since this is much smaller than O(2n) for any reasonably bounded W, DP is the practical choice for solving 0/1 Knapsack.
✓ Summary: The recurrence is correct because every decision (include or exclude) uses previously computed optimal answers. The complexity is O(nW) because we fill each of the (n+1)(W+1) cells exactly once with constant-time work. The table is both a storage device and a proof that we never recompute anything.
